# Practice database

A small online shop: 67 customers, 17 products, 162 orders, 268 order lines. The data is deliberately a little messy, like real data: inconsistent city spellings, padded or uppercase emails, missing segments, cancelled and refunded orders, products nobody has bought, and one unusually large order.

To load it, save the SQL block below as `practice.sql` and run `sqlite3 practice.db < practice.sql`, or in Python: `sqlite3.connect('practice.db').executescript(open('practice.sql').read())`.

## Tables

- **customers**: one row per customer. `segment` is 'consumer', 'small_business' or NULL.
- **products**: one row per product, with its current list `price`.
- **orders**: one row per order. `status` is 'completed', 'cancelled' or 'refunded'.
- **order_items**: one row per product in an order. `unit_price` is what was actually charged, which can be below list price.

```sql
CREATE TABLE customers (
  customer_id INTEGER PRIMARY KEY,
  name        TEXT NOT NULL,
  email       TEXT,
  city        TEXT,
  segment     TEXT,            -- 'consumer', 'small_business' or NULL when unknown
  signup_date TEXT NOT NULL    -- ISO date, YYYY-MM-DD
);
CREATE TABLE products (
  product_id INTEGER PRIMARY KEY,
  name       TEXT NOT NULL,
  category   TEXT NOT NULL,
  price      REAL NOT NULL       -- current list price
);
CREATE TABLE orders (
  order_id    INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL REFERENCES customers(customer_id),
  order_date  TEXT NOT NULL,     -- ISO date
  status      TEXT NOT NULL      -- 'completed', 'cancelled' or 'refunded'
);
CREATE TABLE order_items (
  order_id   INTEGER NOT NULL REFERENCES orders(order_id),
  product_id INTEGER NOT NULL REFERENCES products(product_id),
  quantity   INTEGER NOT NULL,
  unit_price REAL NOT NULL,      -- price actually charged, may differ from list price
  PRIMARY KEY (order_id, product_id)
);
```
